# ADR 0001：独立游戏 workspace 与静态合集

日期：2026-11-13。状态：采用。目录边界更新于 2026-11-19。

## 背景与目标

项目由一款游戏扩展为 `gpt6-astra-demos` 作品集合，需要统一入口、统一构建和可独立分发的 HTML，同时保留每款游戏的模块边界和技术选型。

## 决策

- Game Remakes 仓库按模型设置一级目录。Astra 合集的构建入口、锁文件、游戏和下载成品归入 `gpt6-astra/`。其他模型可在各自目录选择技术栈，也可使用相同的游戏 id。下文的根目录均指 Astra 合集目录。
- 各游戏放在 `games/<id>/`，自行声明依赖和构建 / 测试脚本，不跨游戏导入运行时。
- 使用 npm 内置 workspaces 和单个根锁文件；不用额外构建平台，也不预建共享游戏引擎。
- 根目录 `demos.json` 是可玩作品的注册入口。根构建验证清单与实际路径后，调用游戏的 `build:single`，收集为 `dist/<id>/index.html`。
- 首页从清单生成，可直接进入、搜索或下载作品。预览图、样式和交互内嵌，合集无远程运行依赖。
- 根构建先写临时目录，全部成功后替换已有合集。已有 `dist` 必须带本项目 manifest，避免覆盖无关目录；失败时保留旧产物。
- 首页与游戏之间只共享构建元信息和导航链接，不共享可变游戏状态。战绩仍由各游戏在用户浏览器保存。

## 影响与限制

统一 `npm ci` 安装全部 workspace；每个游戏保持独立依赖声明，但不再维护冲突的多个锁文件。复制单个游戏源码到另一个仓库时，需要重新建立该仓库的锁文件。

单 HTML 是当前合集的发布契约。未来有真实服务端游戏时，应重新评估发布方式，不能把不支持独立运行的游戏静默包装成离线作品。

生产站点全由静态产物组成。调整本地源码目录不会自动变更服务器；部署始终是单独的明确动作。迁移期间保留原始资料和旧产物，私有配置继续被全层级忽略规则排除。
