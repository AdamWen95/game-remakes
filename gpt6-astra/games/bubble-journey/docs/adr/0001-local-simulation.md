# ADR 0001：本地确定性规则模型与独立渲染

日期：2026-11-11。状态：采用。

## 背景

目标是单人对战三个 AI 的纯静态网页竞技游戏，需要连锁爆炸、实时逃生、暂停和可重复验收。没有联机或后端要求。游戏规则如果直接耦合到 Phaser 图形对象 / 补间，会使碰撞时序、同时淘汰与暂停难以独立测试，也容易让帧率改变结果。

## 决策

1. 使用纯 TypeScript `Match` 作为唯一规则状态，Phaser 只负责驱动、渲染与特效，DOM 承载可访问的菜单和操作。
2. 用 60 Hz 固定模拟步长累计真实 delta；关闭 Phaser 默认 delta 平滑。每帧最多接收 100ms 时间，禁止无限追赶。
3. 格子决定可通行性，角色在相邻格间插值；爆炸碰撞取最近格，保持所有 AI 和人类玩家规则一致。
4. 对局选项和地图使用 seed；AI 用同源规则、BFS 与时间危险区间判断，不读取渲染层，不拥有作弊接口。
5. 浏览器本地保存偏好和完成对局，存档独立校验版本和字段，不建设账号、服务端或同步系统。
6. 角色 / 地图以代码生成，音效用 Web Audio 合成，避免原版版权资源与运行时外部素材请求。

## 影响与取舍

- 可以直接运行大量确定性规则场景；真实浏览器测试仍需单独覆盖输入、时间、布局、音频解锁与结果页面。
- 当前碰撞不是自由圆形物理，换格中点是伤害所属格的边界；此规则应稳定保持或在玩法说明中显式调整。
- 阻塞超过 100ms 的帧会损失超出部分的模拟时间，以限制单帧工作量；页面失焦主动暂停。极低帧设备不承诺现实时间一致性。
- localStorage 是本机便利功能，不是可信竞赛分数。若将来增加联机，必须重新定义服务端权威时钟、所有权、事件同步与反作弊，不得直接把当前客户端状态当可信输入。
- 没有引入通用 ECS、多人协议、持久化数据库或多主题插件框架；目前只有一个实际竞技模式，现有模块职责足够。

## 验证与后续条件

规则回归、30 场种子模拟、真实浏览器完整对局和 Linux Nginx 生产包验收分别记录在 `docs/VERIFICATION.md`。出现第二个真实玩法模式或多人需求时再评估共享规则抽象；不为推测场景增加兼容层。
