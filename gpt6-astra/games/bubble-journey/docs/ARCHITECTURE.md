# 架构与维护说明

核对日期：2026-11-11。

## 边界与数据流

```text
DOM 大厅 / 键盘 / 触屏
           ↓ 选择参数、移动方向、单次放弹
ArenaScene（Phaser，60 Hz 固定时间步驱动）
           ↓                         ↑ 只读观察
Match（唯一规则状态） ← 行动指令 ← Brain × 3
           ↓ GameEvent
Phaser 画面 / Sound / DOM HUD / Storage
```

`Match` 不依赖浏览器或 Phaser，可直接在 Node 中运行。移动、放弹、得分、淘汰只能经其规则入口执行。UI 只提交经过控件限定的对局选项，战绩数据读取时单独校验。项目是单用户本地游戏，无服务端、多租户数据或身份授权；浏览器战绩不适合用作可信排行榜。关键决策与取舍见 [ADR 0001](adr/0001-local-simulation.md)。

`ArenaScene` 管理渲染与游戏时钟；大厅预览不会执行规则。固定步长为 1/60 秒，单帧累积最多 100ms，避免后台 / 卡顿后无限追赶。窗口失焦或页面隐藏时自动暂停，继续需显式交互。慢于 10 FPS 的极端设备会降低游戏时间推进速度，优先维持规则稳定，不适合精确现实时间竞赛。

## 关键不变量

- 地图为 15×13 格，边界与固定支柱不可通过。四个角提供等价的初始活动空间和转弯逃生路线；外围可破坏障碍分布由种子生成。
- 一次只能向相邻格发起移动，移动期间不能改变目的格，因此不能对角穿墙。目标落格坐标精确归一，长按与 Pointer Events 仅表示方向意图。
- 爆炸碰撞使用角色当前位置四舍五入到最近格；换格中点即进入新格的伤害范围。视觉会在相邻格之间平滑插值。
- 放弹容量按当前存活泡泡数量计算；同格不可重复放弹。角色能离开自己脚下的泡泡，但不能走入任何有泡泡的目的格。
- 爆炸范围先计算，再破坏箱子。因此单颗炸弹不能穿过自己刚破坏的箱子；随后另一颗炸弹可以经过已打开的通道。
- 炸弹先从容器移除再触发相邻炸弹，避免递归环；最大同时炸弹为 4×5=20。AI 的预测轮数以炸弹数量为界，BFS 最多 195 格、深度 14。
- 所有到期炸弹和连锁爆炸处理完，再统一计算角色淘汰和胜者，防止循环顺序产生虚假胜利。
- 自我淘汰不加分，道具 / 范围 / 速度都有上限，结算只发生一次。多重火焰重合时，淘汰归因于先建立该格火焰的炸弹。
- 暂停不推进炸弹、移动、AI、倒计时和对局时间；关闭输入时清除所有按键状态，避免恢复后粘键。

## AI 决策

AI 在格中心决策，每次先检查当前和未来危险；用炸弹链式时间传播生成危险区间，再用 BFS 搜索安全点。安全时优先拿可达道具，随后寻找可破坏障碍或对手附近的攻击位置。只有假设新增炸弹后还能找到安全出口才放弹。普通与高手区别为决策间隔 / 放弹冷却。

这是有界的局部规划，不是全局最优策略。其他角色之后新放的炸弹、未来多个箱子的动态拆除仍可能使计划失效，AI 会重新预测但仍可能被击中。此限制保留了可对抗性，不能把“有逃生检查”理解成不会失误。

## 美术、音频与性能

- 原创 SVG 角色共享于 DOM 与 Phaser，纹理以两倍画布尺寸生成一次。每个角色有正面 / 背面纹理；朝向、翻转、摆动和轻微缩放形成动画。
- 静态地砖 / 障碍只在开局生成，爆炸仅移除受影响箱子。角色与道具按纵坐标排序，保留俯视层次。
- 活跃粒子上限 160，结束即释放；重新开局清理旧显示对象、贴图引用映射与补间。纹理在游戏生命期复用。
- DOM HUD 每 100ms 更新；AI 只在落格后决策。不会逐帧创建地图或重新生成角色纹理。
- Web Audio 节点在音符结束时断开，音乐定时器在暂停 / 退出时清理。自动播放需用户手势；静音和音乐选择在本地保存。
- 生产使用 WebGL 优先、Canvas 后备；系统减少动态效果时取消粒子、抖动和震屏。实际 GPU / 声卡效果应另做真机测试。

## 开发诊断与恢复

开发模式提供只读 `window.__bubbleSnapshot()`，返回序列化副本供 Playwright 检查规则推进；没有写状态、立即获胜或跳关入口。Vite 生产构建会删除该入口。

存档键为 `bubble-journey-v1`，包含版本与最近战绩。非法存档回退到默认设置，不删除原始键；用户后续交互触发正常覆盖。暂无迁移要求；若将来改格式，应新增版本并提供显式转换，不能把历史记录当新结构直接读取。

无服务端数据迁移。部署回退仅切换静态目录软链接，浏览器存档沿用 v1。已运行的页面继续使用内存中的旧代码，刷新后切到新版本。
